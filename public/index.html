      Technology

      LangGraph

      LangGraph runs the agent loop as a small graph. One node calls the model. One node applies the model's moves to the grid. The graph stops when the model submits the grid, or when the turn limit is reached. A deterministic Python grid engine validates every letter, so the model is never trusted about grid state — only about answers.

      Puzzle generation

      Press "Generate" and the demo makes a puzzle that did not exist before. A backtracking search over a shipped wordlist fills the grid, so every entry is a real word and every crossing agrees. The model then writes the clues. Both services then race to solve it blind — each receives the clues only, never the answers. The answer key is used at the end, to score them.

      Nebius Token Factory

      Nebius serves the models the agent uses by default. It speaks the OpenAI chat API, so the same client code reaches it with only a change of host and key. DeepSeek V4 Pro on Nebius solves every sample puzzle. One puzzle costs a fraction of a cent.

      Two services, one agent

      The dropdown selects the model, and each model is pinned to the service that runs it: Nebius Token Factory, or Vercel AI Gateway. Nothing else changes between them. Use it to compare the same agent, on the same puzzle, across two providers.

      The assignment, and how Jared extended it

      Build an AI agent capable of solving crossword puzzles.

      We gave a language model four tools: get_state, fill_slot, clear_slot, and submit. The model reads the clues and proposes answers. The grid engine checks every letter and rejects answers that break crossing words. The model sees each rejection and corrects itself. The loop ends when the model submits a complete, consistent grid.

      A working implementation of the agent.

      This page is the working agent. Select a puzzle, press Solve, and watch the log. The agent solves all four sample puzzles with 100% accuracy. You can also run it locally from the command line — the README shows how.

      A proposed evaluation methodology for measuring the quality of its solutions.

      We measure three things: letter accuracy, word accuracy, and solved rate. We repeat each run, because model output varies. Baselines bracket the score: an empty grid scores 0%, the answer key scores 100%, and a wordlist filler that ignores clues scores about 10%. The gap between that filler and the agent isolates real clue understanding. We also record turns and token cost per solve.

      A GitHub repository containing the source code and clear instructions for running the project.

      The code is public at github.com/jaredwerba/Nebius-XWord. The README shows setup in four commands. The tests run without an API key. Pushes to main deploy this page automatically.

      Beyond the assignment.

      Jared extended the brief in five ways. The page carries Nebius branding — logo, colors, and type. A live log streams every move, with a clock and a time estimate. A generator builds puzzles that did not exist before, and the agent solves them blind. The agent runs on two services: DeepSeek and Qwen on Nebius Token Factory — chosen for tool calling and for speed — and the same DeepSeek weights on Vercel AI Gateway. A race fires both services at once and charts the result, so the speed difference is measured and not claimed.
